# Статистика кампаний Wildberries через `/adv/v3/fullstats`

`GET /adv/v3/fullstats` запрашивает статистику кампаний со статусами `7`, `9` и `11`. В одном HTTP-запросе допустимо до 50 ID и до 31 календарного дня. ID передаются через запятую в `ids`, границы периода — в `beginDate` и `endDate`. [Документация WB по продвижению](https://dev.wildberries.ru/openapi/promotion)

Для автоматического отбора статусов нужна версия MP API с настройкой `reference.filter`.

## 1. Возьмите ID шаблона `/adv/v1/promotion/count`

1. Откройте **Шаблоны запросов** и выберите подключение, в котором у вас уже работает `/adv/v1/promotion/count`. В готовом пакете этот шаблон называется **1. Списки кампаний WB** и находится в **Поисковых кластерах**.
2. Через **Ещё → Версии** раскройте последнюю опубликованную версию. Проверьте, что в `response.rows` указано `adverts`. Это сохраняет по одной записи на группу кампаний, где `status` и `advert_list` доступны рядом.
3. Скопируйте верхнее поле `id` рядом с `name`. Оно идентифицирует шаблон MP API и будет использовано в `reference.templateId`. Числа `advertId` придут из свежего ответа WB при каждом запуске.

## 2. Создайте шаблон статистики

Выберите то же подключение в **Шаблоны запросов** и нажмите **Новый шаблон**.

| Поле | Значение |
| --- | --- |
| Название | `Статистика кампаний WB` |
| Папка | Например, `Статистика рекламы` |
| Адрес подключения | Адрес с URL `https://advert-api.wildberries.ru` |
| Авторизация | Тот же профиль `Authorization`, что у списка кампаний |
| Метод | `GET` |
| Путь запроса | `/adv/v3/fullstats` |
| Пагинация и период → Механизм | **Без пагинации**, JSON правил `{"type":"none"}` |

В **Параметры запроса → Определения параметров** вставьте весь массив. Вместо `ID-ИЗ-ВЕРСИИ-СПИСКА` вставьте значение из шага 1.

```json
[
  {
    "name": "ids",
    "label": "ID кампаний",
    "where": "query",
    "type": "array",
    "items": { "type": "integer", "min": 1 },
    "required": true,
    "minItems": 1,
    "batchSize": 50,
    "encoding": "csv",
    "reference": {
      "templateId": "ID-ИЗ-ВЕРСИИ-СПИСКА",
      "mode": "all",
      "refresh": "run",
      "filter": { "path": "status", "values": [7, 9, 11] },
      "expand": "advert_list",
      "path": "advertId"
    }
  },
  {
    "name": "beginDate",
    "label": "Начало периода",
    "where": "query",
    "type": "date",
    "required": true
  },
  {
    "name": "endDate",
    "label": "Конец периода",
    "where": "query",
    "type": "date",
    "required": true
  }
]
```

- `refresh: "run"` выполняет опубликованный список в начале каждого запуска статистики.
- `filter` сначала отбирает группы по полю `status`. Затем `expand` открывает `advert_list` каждой подходящей группы, а `path` берёт из его элементов `advertId`. `mode: "all"` собирает уникальные ID.
- `batchSize: 50` делит полученный список на части. `where: "query"` и `encoding: "csv"` превращают каждую часть в значение `ids` в строке запроса. Например, `GET /adv/v3/fullstats?ids=22161678,28449281&beginDate=2026-11-20&endDate=2026-11-21`.

В **Пагинация и период → Разбиение периода (JSON)** вставьте объект.

```json
{"from":"beginDate","to":"endDate","daysPerRequest":31}
```

`from` и `to` ссылаются на имена параметров дат. Приложение проверяет их порядок и делит длинный диапазон на части по 31 календарному дню с учётом обоих краёв. Например, 51 ID на 33 дня дадут четыре запроса статистики. Это две части списка, у каждой по две части периода.

## 3. Настройте столбцы и листы Excel

В **Ответ и колонки → Путь к массиву строк** введите `$`. Успешный ответ WB начинается с массива. Каждая запись содержит `advertId` и показатели кампании за отправленную часть периода.

В большое поле **Колонки** под кнопкой **Добавить колонку** вставьте настройки основного листа.

```json
[
  { "path": "advertId", "name": "ID кампании" },
  { "path": "request.beginDate", "name": "Начало периода" },
  { "path": "request.endDate", "name": "Конец периода" },
  { "path": "currency", "name": "Валюта" },
  { "path": "views", "name": "Просмотры" },
  { "path": "clicks", "name": "Клики" },
  { "path": "ctr", "name": "CTR" },
  { "path": "cpc", "name": "CPC" },
  { "path": "cr", "name": "CR" },
  { "path": "atbs", "name": "Добавления в корзину" },
  { "path": "orders", "name": "Заказы" },
  { "path": "shks", "name": "Заказано товаров, шт." },
  { "path": "canceled", "name": "Отмены" },
  { "path": "sum", "name": "Расходы" },
  { "path": "sum_price", "name": "Сумма заказов" }
]
```

В поле **Проверка успеха, массивы и дедупликация (JSON)** ниже вставьте объект с правилами ответа.

```json
{
  "requestFields": { "beginDate": "beginDate", "endDate": "endDate" },
  "tables": [
    {
      "name": "Кампании по дням",
      "path": "days",
      "columns": [
        { "path": "$parent.advertId", "name": "ID кампании" },
        { "path": "date", "name": "Дата" },
        { "path": "$parent.currency", "name": "Валюта" },
        { "path": "views", "name": "Просмотры" },
        { "path": "clicks", "name": "Клики" },
        { "path": "ctr", "name": "CTR" },
        { "path": "cpc", "name": "CPC" },
        { "path": "cr", "name": "CR" },
        { "path": "atbs", "name": "Добавления в корзину" },
        { "path": "orders", "name": "Заказы" },
        { "path": "shks", "name": "Заказано товаров, шт." },
        { "path": "canceled", "name": "Отмены" },
        { "path": "sum", "name": "Расходы" },
        { "path": "sum_price", "name": "Сумма заказов" }
      ]
    },
    {
      "name": "Средняя позиция",
      "path": "boosterStats",
      "columns": [
        { "path": "$parent.advertId", "name": "ID кампании" },
        { "path": "date", "name": "Дата" },
        { "path": "nm", "name": "Артикул WB" },
        { "path": "avg_position", "name": "Средняя позиция" }
      ]
    }
  ]
}
```

`requestFields` добавляет к каждой записи фактические границы её запроса. Если одна кампания запрашивается за несколько частей периода, эти колонки различают её строки. `tables` разворачивает `days` и `boosterStats` в отдельные листы. `$parent.advertId` берёт ID кампании верхнего уровня. Лист **Средняя позиция** заполняется, когда WB присылает `boosterStats`.

## 4. Поставьте лимит и проверьте первый запрос

Для персонального токена в **Лимиты и восстановление → Дополнительные ограничения (JSON)** вставьте массив.

```json
[{ "id": "wb-fullstats", "type": "bucket", "refillMs": 20000, "burst": 1 }]
```

`20000` миллисекунд — 20 секунд между запросами, то есть до трёх в минуту. Тот же лимит указан для сервисного и базового токена с секретом. Для обычного базового токена у метода один запрос в час, что соответствует `refillMs: 3600000` и `burst: 1`. Для этого `GET` можно включить **Безопасно повторять при временной ошибке**.

Нажмите **Сохранить и протестировать**, выберите **Рабочая** и задайте даты, например `2026-11-20` и `2026-11-21`. **Выполнить запрос** сначала загрузит список кампаний, затем выполнит одну часть статистики, до 50 ID и до 31 дня. В **Журнал → Подробнее** откройте **Параметры запуска** у статистики, чтобы увидеть отобранные ID и общий диапазон. Здесь же через **Просмотр строк** можно проверить фактические границы `request.beginDate` и `request.endDate` первого ответа.

Исходный JSON WB доступен через **Шаблоны запросов → Ещё → Образец ответа**. Если список не содержит групп со статусами `7`, `9` или `11`, в журнале появится сообщение о пустом списке для параметра **ID кампаний**.

## 5. Создайте полную выгрузку

1. У шаблона статистики нажмите **Настроить → Сохранить и опубликовать версию**.
2. В **Выгрузки → Создать выгрузку** выберите подключение, папку и один источник **Статистика кампаний WB**. Выберите **Рабочая**, **Без обработки** и **Excel (.xlsx)**. Приложение выполнит список как зависимый запрос.
3. Для одинакового периода при каждом запуске выберите **Фиксированная** у начала и конца и укажите нужные даты. Для двух последних завершённых дней у обеих дат выберите **Относительно дня запуска**. Поставьте `-2` для начала и `-1` для конца. Динамические даты рассчитываются по календарю компьютера при постановке запуска в очередь.
4. Сохраните и запустите выгрузку или настройте расписание. Откройте **Журнал → Подробнее → Открыть папку файлов**. Полная выгрузка выполняет все части списка и периода.

## Товары по дням и платформам

Для отдельного файла на уровне товара откройте **Обработки → Новая обработка**, выберите этот шаблон и включите режим **JSON**. Три шага разворачивают `days`, затем `apps`, затем `nms`.

```json
{
  "steps": [
    { "type": "expandArray", "path": "days", "as": "day" },
    { "type": "expandArray", "path": "day.apps", "as": "app" },
    { "type": "expandArray", "path": "app.nms", "as": "item" }
  ],
  "columns": [
    { "path": "advertId", "name": "ID кампании" },
    { "path": "day.date", "name": "Дата" },
    { "path": "app.appType", "name": "Тип платформы" },
    { "path": "item.nmId", "name": "Артикул WB" },
    { "path": "item.name", "name": "Название товара" },
    { "path": "currency", "name": "Валюта" },
    { "path": "item.views", "name": "Просмотры" },
    { "path": "item.clicks", "name": "Клики" },
    { "path": "item.ctr", "name": "CTR" },
    { "path": "item.cpc", "name": "CPC" },
    { "path": "item.atbs", "name": "Добавления в корзину" },
    { "path": "item.orders", "name": "Заказы" },
    { "path": "item.shks", "name": "Заказано товаров, шт." },
    { "path": "item.canceled", "name": "Отмены" },
    { "path": "item.sum", "name": "Расходы" },
    { "path": "item.sum_price", "name": "Сумма заказов" }
  ]
}
```

Проверьте **Предпросмотр** на сохранённом запуске и сохраните обработку. В **Журнал → Подробнее → Применить обработку** выберите её у статистики, чтобы открыть отдельный Excel из уже полученных данных. Одна строка соответствует товару в конкретной кампании, дате и платформе.
