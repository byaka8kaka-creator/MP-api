# Отгрузки первой мили по нескольким магазинам Яндекс Маркета

Шаблон **Отгрузки первой мили** может использовать список `campaignId` из другого запроса. При запуске выгрузки MP API обновляет список магазинов, затем выполняет `PUT /v2/campaigns/{campaignId}/first-mile/shipments` для каждого уникального ID и собирает страницы в один результат.

## 1. Возьмите ID шаблона списка магазинов

1. В **Шаблоны запросов → Яндекс Маркет** найдите готовый шаблон списка. Проверьте, что он опубликован и использует то же подключение, что и отгрузки.
2. Откройте **Ещё → Образец ответа**. Посмотрите, какое поле в каждой записи содержит числовой ID магазина. Например, если в ответе есть `{"campaigns":[{"id":123},{"id":456}]}`, путь к массиву строк шаблона списка — `campaigns`, а поле внутри строки — `id`.
3. В **Ещё → Версии** раскройте последнюю опубликованную версию и скопируйте верхнее поле `id` рядом с `name`. Его значение понадобится в `reference.templateId`.
4. Если у списка есть обязательные входные параметры, задайте их значения через `default` в шаблоне списка и опубликуйте его. Зависимый запуск получает значения из этого шаблона.

## 2. Настройте `campaignId` в шаблоне отгрузок

Откройте **Отгрузки первой мили → Настроить → Параметры запроса**. В массиве параметров замените объект с `"name": "campaignId"` следующим объектом. В `templateId` вставьте скопированный ID. В `reference.path` укажите поле внутри одной записи, например `id` или `campaignId`.

```json
{
  "name": "campaignId",
  "label": "ID магазинов",
  "where": "path",
  "type": "array",
  "items": { "type": "integer", "min": 1 },
  "minItems": 1,
  "batchSize": 1,
  "encoding": "csv",
  "reference": {
    "templateId": "ID-ШАБЛОНА-СПИСКА",
    "mode": "all",
    "refresh": "run",
    "path": "id"
  }
}
```

`refresh: "run"` запускает запрос списка при каждой выгрузке. `mode: "all"` собирает все уникальные значения. `batchSize: 1` берёт один ID за раз, а `encoding: "csv"` передаёт его в пути как число без скобок. Из `[123,456]` получатся два вызова по путям `/v2/campaigns/123/first-mile/shipments` и `/v2/campaigns/456/first-mile/shipments`. Параметры дат и фильтров применяются к каждому магазину.

В **Пагинация и период** проверьте механизм **Строковый токен**. Поля `target`, `parameter` и `cursor` должны содержать `query`, `pageToken` и `result.paging.nextPageToken` соответственно. Для первого запроса используется исходный адрес магазина. Последующие страницы запрашиваются с токеном из ответа этого магазина.

## 3. Добавьте ID магазина в результат

В **Ответ и колонки** укажите `result.shipments` в поле **Путь к массиву строк**. В поле **Проверка успеха, массивы и дедупликация (JSON)** добавьте свойство `requestFields` к существующим правилам. Например, для стартового шаблона подойдёт такой объект.

```json
{
  "success": { "path": "status", "equals": "OK" },
  "requestFields": { "campaignId": "campaignId.0" }
}
```

`campaignId.0` берёт первый и единственный ID из отправленной части списка. Для вывода в Excel укажите `request.campaignId` в поле **Путь поля** и **ID магазина** в поле **Имя колонки**, затем нажмите **Добавить колонку**.

## 4. Проверьте и запустите цепочку

1. Нажмите **Сохранить и протестировать**, заполните даты и нажмите **Выполнить запрос**. Тест выполнит зависимый список и прочитает первую страницу отгрузок первого магазина.
2. В **Журнал → Подробнее** найдите карточку **Зависимый запрос** и карточку отгрузок. В **Параметры запуска** основного источника будут собранные ID. Через **Просмотр строк** можно проверить `request.campaignId`.
3. Вернитесь в **Настроить → Сохранить и опубликовать версию**. В **Выгрузки → Создать выгрузку** достаточно добавить один источник **Отгрузки первой мили**. Укажите период, формат и при необходимости расписание.
4. Сохраните и нажмите **Запустить**. Полный запуск пройдёт по всем магазинам и по всем страницам для каждого магазина. Готовые файлы доступны в **Журнал → Подробнее → Открыть папку файлов**.
