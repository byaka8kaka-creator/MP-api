# Статистика поисковых кластеров Wildberries

MP API перед каждым новым запуском загружает кампании и актуальный состав товаров. В выгрузку добавляется шаблон **Статистика поисковых кластеров WB по дням**. Два остальных шаблона выполняются как зависимости.

| Порядок | Запрос | Как используются данные |
| --- | --- | --- |
| 1 | `GET /adv/v1/promotion/count` | Из всех групп `adverts[].advert_list[]` собираются уникальные `advertId` |
| 2 | `GET /api/advert/v3/adverts` | По этим ID загружаются кампании. Для каждого элемента `adverts[].nms[]` берётся его `nmId` и `advertId` родительской кампании |
| 3 | `POST /adv/v1/normquery/stats` | В JSON уходят даты `from`, `to` и до 100 пар `{advertId, nmId}` за один HTTP-запрос |

Если товар есть в нескольких кампаниях, в `items` будет по одной паре на каждую из них. Одинаковые пары в одной выгрузке удаляются. Для всех частей статистики используются даты и пары этого запуска. При пустом списке кампаний или пар соответствующие сетевые шаги пропускаются. Ошибка или частичная загрузка зависимости останавливает запрос статистики и видна в журнале.

## Импорт готовых шаблонов

1. Обновите MP API до версии с поддержкой зависимостей при запуске. В свежем ZIP найдите [examples/wb-search-clusters.json](../examples/wb-search-clusters.json).
2. В разделе **API-запросы** нажмите **Импорт пакета** и выберите этот файл. Откройте **Wildberries · Продвижение**. В папке **Поисковые кластеры** появятся три черновика.
3. В разделе **Авторизация** выберите адрес **Продвижение**, профиль **Токен Wildberries** и среду **Рабочая**. В поле `Authorization` введите токен Wildberries с доступом к категории «Продвижение». Формат — сам токен, без префикса `Bearer`. Ключ для этого адреса хранится локально.
4. Откройте каждый черновик через **Настроить** и нажмите **Сохранить и опубликовать версию**. Порядок публикации **1. Списки кампаний WB → 2. Состав кампаний WB → 3. Статистика поисковых кластеров WB по дням**. При публикации MP API проверяет ссылки на уже опубликованные шаблоны.
5. Нажмите **Тест** у третьего шаблона и задайте начало и конец периода. Пример относительных дат для двух последних завершённых дней — `-2` для начала и `-1` для конца. Тест выполняет оба зависимых шага полностью и отправляет первую часть статистики. Его результат доступен в **Журнал → Подробнее**, пример ответа — через **Ещё → Образец ответа** у шаблона.
6. Для полного результата создайте выгрузку с третьим шаблоном. Укажите период, формат и при необходимости расписание. После запуска **Подробнее** покажет шаги цепочки. Кнопка **Открыть папку файлов** ведёт к результату статистики. Поле пар заполняется автоматически.

В заготовке настройки лимитов соответствуют персональному, сервисному и базовому токену с секретом. Для обычного базового токена измените значения в **Лимиты и восстановление → Дополнительные ограничения (JSON)** у каждого шаблона и опубликуйте версии заново.

| Шаблон | `refillMs` для базового токена | `burst` |
| --- | ---: | ---: |
| Списки кампаний WB | 900000 | 1 |
| Состав кампаний WB | 3600000 | 1 |
| Статистика поисковых кластеров WB | 1800000 | 1 |

Для запроса состава кампаний в пакете установлен размер части **50 ID**. Для статистики используется максимум **100 пар** на HTTP-запрос. Настройка числа элементов находится в свойстве `batchSize` соответствующего параметра.

## Настройка вручную

Создайте три шаблона на одном подключении с адресом `https://advert-api.wildberries.ru` и авторизацией через заголовок `Authorization`. Используйте **Без пагинации** для каждого из трёх шаблонов. В режиме запроса состава по конкретным кампаниям достаточно одного параметра `advertIds` на часть.

1. **Списки кампаний.** Метод `GET`, путь `/adv/v1/promotion/count`, параметры `[]`, путь к массиву строк ответа `adverts`. Сохраните и опубликуйте. Для ручной ссылки узнайте ID шаблона через **Ещё → Экспорт шаблона**. Найдите поле `id` объекта этого метода в массиве `templates` экспортированного JSON.
2. **Состав кампаний.** Метод `GET`, путь `/api/advert/v3/adverts`, путь к массиву строк ответа `adverts`. В **Параметры запроса** вставьте значение ниже. Подставьте фактический ID опубликованного шаблона списков кампаний и опубликуйте шаблон состава.

   ```json
   [
     {
       "name": "advertIds",
       "label": "ID кампаний",
       "where": "query",
       "type": "array",
       "items": { "type": "integer", "min": 1 },
       "required": true,
       "minItems": 1,
       "encoding": "csv",
       "batchSize": 50,
       "reference": {
         "templateId": "ID-ШАБЛОНА-СПИСКОВ",
         "mode": "all",
         "refresh": "run",
         "expand": "advert_list",
         "path": "advertId"
       }
     }
   ]
   ```

3. **Статистика кластеров.** Метод `POST`, путь `/adv/v1/normquery/stats`, путь к массиву строк ответа `items`. Вставьте параметры ниже, подставив фактический ID шаблона состава. В поле **Разбиение периода (JSON)** укажите `{"from":"from","to":"to"}` для проверки порядка дат.

   ```json
   [
     { "name": "from", "label": "Начало периода", "where": "body", "type": "date", "required": true },
     { "name": "to", "label": "Конец периода", "where": "body", "type": "date", "required": true },
     {
       "name": "items",
       "label": "Пары кампаний и артикулов",
       "where": "body",
       "type": "array",
       "items": {
         "type": "object",
         "properties": {
           "advertId": { "type": "integer", "min": 1, "required": true },
           "nmId": { "type": "integer", "min": 1, "required": true }
         }
       },
       "required": true,
       "minItems": 1,
       "batchSize": 100,
       "reference": {
         "templateId": "ID-ШАБЛОНА-СОСТАВА",
         "mode": "all",
         "refresh": "run",
         "expand": "nms",
         "fields": { "advertId": "$parent.advertId", "nmId": "nmId" }
       }
     }
   ]
   ```

4. Перенесите правила лимитов каждого метода из готового пакета в раздел **Лимиты и восстановление** и включите безопасные повторы. Эти три метода читают данные. Для обычных пользователей разрешите доступ ко всем трём шаблонам и опубликуйте их по порядку.
5. Для первого теста оставьте колонку с корневым путём `$`. После получения образца ответа можно выбрать отдельные колонки по фактическим полям массива `items`.

В ссылках выше `expand` выбирает вложенный массив в каждой строке зависимого ответа. `path` берёт одно значение из его элемента. `fields` создаёт объект, а путь с `$parent.` читает поле родительской строки. Так `advertId` и `nmId` остаются связанными.

## Обработка статистики по дням

1. В **Обработки → Новая обработка** выберите шаблон **3. Статистика поисковых кластеров WB по дням** и сохраните обработку **Поисковые кластеры WB по дням**.
2. Чтобы обработать сохранённый ответ, откройте **Журнал → Подробнее → Применить обработку** у основного запроса. Выберите XLSX или CSV и нажмите **Создать файл**. Результат доступен через **Открыть обработанные файлы**.
3. Для новых запусков выберите обработку в настройках источника в разделе **Выгрузки**.

Каждый элемент `dailyStats` становится отдельной строкой с колонками `advertId`, `nmId`, `date` и показателями из `stat`. Несколько записей за одну дату сохраняются отдельными строками. Записи с отсутствующим или пустым `dailyStats` пропускаются. Список колонок можно изменить в настройках обработки.
