# Статистика медиакампаний Wildberries

Метод `POST /adv/v1/stats` принимает от 1 до 100 объектов кампаний в корневом массиве JSON. У каждого объекта `id` — это число из поля `advertId` ответа **Списка медиакампаний** (`GET /adv/v1/adverts`). Для запроса по конкретным датам рядом с `id` передаётся массив `dates`. [Документация WB по продвижению](https://dev.wildberries.ru/openapi/promotion)

Для настройки нужна версия MP API с поддержкой `"key": "$"` у параметра тела. Эта инструкция сохраняет ID кампании в Excel. В успешном ответе WB указывает `item_id` баннера, поэтому запрашиваем по одной кампании и переносим её ID из отправленного JSON.

## 1. Создайте шаблон

Откройте **Шаблоны запросов**, выберите подключение, в котором уже работает **Список медиакампаний**, и нажмите **Новый шаблон**. Используйте адрес и профиль авторизации, на которых у вас работает `/adv/v1/advert`.

| Поле | Значение |
| --- | --- |
| Название | `Статистика медиакампаний WB` |
| Папка | Например, `Медиакампании` |
| Адрес подключения | Адрес с URL `https://advert-media-api.wildberries.ru` |
| Авторизация | Ваш рабочий профиль `Authorization` для WB Медиа |
| Метод | `POST` |
| Путь запроса | `/adv/v1/stats` |
| Пагинация и период → Механизм | **Без пагинации**, JSON правил `{"type":"none"}` |
| Пагинация и период → Разбиение периода (JSON) | `null` |

Вариант с `dates` передаёт каждую дату внутри объекта кампании. Свойство `batchSize` делит список кампаний на запросы.

## 2. Настройте ручной тест по датам

Раскройте **Параметры запроса** и вставьте этот массив в большое поле **Определения параметров**.

```json
[
  {
    "name": "campaigns",
    "label": "Кампании и даты",
    "where": "body",
    "key": "$",
    "type": "array",
    "required": true,
    "minItems": 1,
    "batchSize": 1,
    "items": {
      "type": "object",
      "properties": {
        "id": { "type": "integer", "required": true, "min": 1 },
        "dates": {
          "type": "array",
          "required": true,
          "minItems": 1,
          "items": { "type": "date", "required": true }
        }
      }
    }
  }
]
```

`campaigns` — имя параметра в приложении. `where: "body"` помещает его в JSON-тело. Значение `key: "$"` отправляет массив целиком в корне. MP API выставляет `Content-Type: application/json`. `batchSize: 1` сохраняет однозначную связь каждой строки ответа с ID кампании из её запроса.

## 3. Настройте ответ и Excel

В **Ответ и колонки → Путь к массиву строк** поставьте `$`. WB возвращает корневой массив. Одна запись в этом массиве может содержать `dates` или `interval` и вложенный массив `stats`. Для ненайденной кампании WB может вернуть запись с `advertId` и `error`.

В большое поле **Колонки** под кнопкой **Добавить колонку** вставьте настройки основного листа.

```json
[
  { "path": "request.campaignId", "name": "ID кампании" },
  { "path": "dates", "name": "Даты" },
  { "path": "interval.begin", "name": "Начало интервала" },
  { "path": "interval.end", "name": "Конец интервала" },
  { "path": "error", "name": "Сообщение WB" }
]
```

В поле **Проверка успеха, массивы и дедупликация (JSON)** ниже вставьте этот объект.

```json
{
  "requestFields": { "campaignId": "campaigns.0.id" },
  "tables": [
    {
      "name": "Статистика баннеров",
      "path": "stats",
      "columns": [
        { "path": "$parent.request.campaignId", "name": "ID кампании" },
        { "path": "$parent.dates", "name": "Даты" },
        { "path": "$parent.interval.begin", "name": "Начало интервала" },
        { "path": "$parent.interval.end", "name": "Конец интервала" },
        { "path": "item_id", "name": "ID баннера" },
        { "path": "item_name", "name": "Название в WB" },
        { "path": "category_name", "name": "Категория" },
        { "path": "advert_type", "name": "Тип медиакампании" },
        { "path": "place", "name": "Место размещения" },
        { "path": "views", "name": "Просмотры" },
        { "path": "clicks", "name": "Клики" },
        { "path": "ctr", "name": "CTR" },
        { "path": "atbs", "name": "Добавления в корзину" },
        { "path": "orders", "name": "Заказы" },
        { "path": "cr", "name": "CR" },
        { "path": "price", "name": "Стоимость размещения" },
        { "path": "cpc", "name": "CPC" },
        { "path": "expenses", "name": "Расходы" },
        { "path": "status", "name": "Статус" },
        { "path": "date_from", "name": "Начало размещения" },
        { "path": "date_to", "name": "Конец размещения" },
        { "path": "cr1", "name": "CR1" },
        { "path": "cr2", "name": "CR2" },
        { "path": "daily_stats", "name": "Детализация по дням (JSON)" }
      ]
    }
  ]
}
```

`requestFields` переносит `campaigns[0].id` отправленной части в `request.campaignId` каждой сохранённой строки. Номер `0` обозначает первый элемент массива. Шаблон проверяет, что для такого переноса задан `batchSize: 1`.

`tables` разворачивает `stats` в отдельный лист. `$parent` обращается к записи верхнего уровня, поэтому рядом с каждой строкой баннера виден ID кампании и период. Поле `item_id` показывает ID баннера. В основном листе можно увидеть сообщения WB, связанные с кампанией. Если `stats` отсутствует или пуст, строк баннеров для этой записи будет ноль.

## 4. Задайте лимит и выполните ручной тест

В **Лимиты и восстановление → Дополнительные ограничения (JSON)** для персонального токена вставьте умеренный лимит. Он использует тот же темп, что уже помог для запроса деталей.

```json
[{ "id": "wb-media-stats", "type": "bucket", "refillMs": 200, "burst": 1 }]
```

Это до пяти запросов в секунду. Для персонального токена документация WB указывает до десяти запросов в секунду. Для обычного базового токена у этого метода лимит один запрос в час, в таком случае `refillMs` равен `3600000`. Можно включить **Безопасно повторять при временной ошибке**, поскольку метод читает статистику.

Нажмите **Сохранить и протестировать**, выберите **Рабочая**. В поле **Кампании и даты** вставьте массив. Подставьте ID из `advertId` вашего списка и даты, когда у кампании были показы.

```json
[{ "id": 23569, "dates": ["2026-11-19", "2026-11-20"] }]
```

Нажмите **Выполнить запрос**. В **Журнал → Подробнее → Параметры запуска** видны введённые значения. У шаблона в **Ещё → Образец ответа** можно открыть исходный ответ WB. В **Журнал → Подробнее → Просмотр строк** видны сохранённые строки, включая добавленное поле `request.campaignId`. При `200` проверьте `stats` и `error` в ответе для конкретной кампании.

## 5. Получайте ID автоматически

У опубликованного шаблона **Список медиакампаний** откройте **Ещё → Версии**, разверните последнюю версию и скопируйте поле `id` рядом с `name`. Это ID шаблона, который указывается в `reference.templateId`.

У статистики откройте **Настроить → Параметры запроса**. Замените ручную настройку следующим массивом и подставьте ID списка вместо `ID-ИЗ-ШАБЛОНА-СПИСКА`.

```json
[
  {
    "name": "dates",
    "label": "Даты статистики",
    "where": "input",
    "type": "array",
    "required": true,
    "minItems": 1,
    "items": { "type": "date", "required": true }
  },
  {
    "name": "campaigns",
    "label": "Медиакампании",
    "where": "body",
    "key": "$",
    "type": "array",
    "required": true,
    "minItems": 1,
    "batchSize": 1,
    "items": {
      "type": "object",
      "properties": {
        "id": { "type": "integer", "required": true, "min": 1 },
        "dates": {
          "type": "array",
          "required": true,
          "minItems": 1,
          "items": { "type": "date", "required": true }
        }
      }
    },
    "reference": {
      "templateId": "ID-ИЗ-ШАБЛОНА-СПИСКА",
      "mode": "all",
      "refresh": "run",
      "fields": { "id": "advertId", "dates": "$input.dates" }
    }
  }
]
```

- `where: "input"` добавляет **Даты статистики** в форму запуска. Эти значения включаются в тело через правило `$input.dates` внутри объекта каждой кампании.
- `reference.fields.id` берёт `advertId` из каждой строки списка. `refresh: "run"` обновляет список перед запуском статистики, а `mode: "all"` собирает уникальные объекты кампаний.
- При автоматическом запуске список использует свои опубликованные настройки. Если при ручной выгрузке вы выбирали фильтры, нужные значения можно задать как `default` в шаблоне списка и опубликовать его.

Сохраните и опубликуйте шаблон. **Тест** выполнит список и отправит первую часть статистики. Обычная выгрузка выполнит все части.

## 6. Создайте выгрузку с фиксированными или динамическими датами

1. Откройте **Выгрузки → Создать выгрузку**, выберите подключение, папку и шаблон **Статистика медиакампаний WB**. Выберите **Рабочая**, **Без обработки** и **Excel (.xlsx)**. В источники достаточно добавить шаблон статистики.
2. В поле **Даты статистики** вставьте один из массивов ниже. Для **фиксированных дат** строки с датами будут использоваться при каждом запуске.

   ```json
   ["2026-11-19", "2026-11-20"]
   ```

   Для **динамических дат** объекты со смещениями берут два последних завершённых дня. MP API определяет даты по календарю компьютера на момент постановки запуска в очередь.

   ```json
   [{ "daysFromRun": -2 }, { "daysFromRun": -1 }]
   ```

3. Сохраните и запустите выгрузку. Для автоматического выполнения задайте расписание в этой же форме. В **Журнал → Подробнее → Открыть папку файлов** доступен Excel с основным листом и **Статистикой баннеров**.

## Вариант с интервалом или только ID

Документация также описывает `RequestWithInterval` и `RequestWithCampaignID`. Для понимания формы тела можно сравнить эти примеры.

```json
[{ "id": 23569, "interval": { "begin": "2026-11-19", "end": "2026-11-20" } }]
```

```json
[{ "id": 23569 }]
```

Чтобы перейти на интервалы, замените весь объект `items.properties` у параметра `campaigns` следующим. Укажите начало и равный ему или более поздний конец.

```json
{
  "id": { "type": "integer", "required": true, "min": 1 },
  "interval": {
    "type": "object",
    "required": true,
    "properties": {
      "begin": { "type": "date", "required": true },
      "end": { "type": "date", "required": true }
    }
  }
}
```

В автоматическом варианте замените первый параметр `dates` новым параметром формы.

```json
{
  "name": "interval",
  "label": "Интервал статистики",
  "where": "input",
  "type": "object",
  "required": true,
  "properties": {
    "begin": { "type": "date", "required": true },
    "end": { "type": "date", "required": true }
  }
}
```

В `reference.fields` параметра `campaigns` задайте `{"id":"advertId","interval":"$input.interval"}`. Теперь в форме **Интервал статистики** у обоих полей `begin` и `end` можно выбрать фиксированную дату или смещение. Для ручного варианта вставьте первый пример запроса в **Кампании и даты**. В ответе по интервалу будут заполнены колонки из `interval.begin` и `interval.end`, а в `stats` останутся показатели баннеров.

Для варианта только по ID оставьте в `items.properties` только определение `id`. В автоматическом шаблоне удалите первый параметр формы и поменяйте `reference.fields` на `{"id":"advertId"}`. В ручном варианте вставьте второй пример тела. Колонки периода для этого формата могут быть пустыми.

## Как вывести детализацию по дням в отдельный файл

В ответе `daily_stats` содержит дневные блоки. Внутри каждого `app_type_stats` разбивает их по типу приложения, а его `stats` содержит показатели. В **Обработки → Новая обработка** выберите этот шаблон и переключитесь на **JSON**. Вставьте настройки ниже.

```json
{
  "steps": [
    { "type": "expandArray", "path": "stats", "as": "banner" },
    { "type": "expandArray", "path": "banner.daily_stats", "as": "day" },
    { "type": "expandArray", "path": "day.app_type_stats", "as": "app" },
    { "type": "expandArray", "path": "app.stats", "as": "stat" }
  ],
  "columns": [
    { "path": "request.campaignId", "name": "ID кампании" },
    { "path": "banner.item_id", "name": "ID баннера" },
    { "path": "day.date", "name": "Дата" },
    { "path": "app.app_type", "name": "Тип приложения" },
    { "path": "stat.views", "name": "Просмотры" },
    { "path": "stat.clicks", "name": "Клики" },
    { "path": "stat.atbs", "name": "Добавления в корзину" },
    { "path": "stat.orders", "name": "Заказы" },
    { "path": "stat.cr", "name": "CR" },
    { "path": "stat.ctr", "name": "CTR" }
  ]
}
```

В **Предпросмотре** выберите сохранённый запуск и проверьте счётчики и образцы. Сохраните обработку. В **Журнал → Подробнее → Применить обработку** выберите её у карточки статистики и нажмите **Создать файл**. В результате одна строка приходится на элемент статистики баннера, даты и типа приложения. Метрики, которые WB не прислал для этой детализации, останутся пустыми.
