# MP API

Локальное приложение для Windows. Создавайте шаблоны HTTP-запросов, собирайте их в выгрузки и сохраняйте данные в Excel или CSV. Первая тестовая версия включает три готовых шаблона.

| Источник | Метод | Настройка |
| --- | --- | --- |
| Wildberries | `GET /api/v3/orders` | Токен в `Authorization`, курсор `next`, интервалы до 30 календарных дней по UTC |
| Ozon Seller | `POST /v2/warehouse/list` | `Client-Id` и `Api-Key`, строковый курсор и `has_next`, до 200 ID на запрос |
| Яндекс Маркет | `PUT /v2/campaigns/{campaignId}/first-mile/shipments` | `Api-Key`, ID магазина, курсор `result.paging.nextPageToken`, до 30 строк на страницу |

## Запуск

Поддерживается Node.js 22.16 или новее. Команды выполняются в папке репозитория. При первом запуске Electron загружает свой бинарный файл.

```powershell
npm ci
npm start
```

Первый вход выполняется с логином `admin` и стартовым паролем `MPadmin2026!`. Приложение сразу попросит задать новый пароль.

1. В разделе **Подключения** откройте нужный API и добавьте ключи через **Авторизацию**. Укажите адрес и среду. Песочница Wildberries использует отдельные ключи.
2. В разделе **Шаблоны запросов** нажмите **Тест** у шаблона. Тест получает первую страницу. Сохранённый образец и обнаруженная структура доступны через **Ещё → Образец ответа**.
3. Создайте выгрузку и выберите источники, формат и при необходимости расписание. Для Маркета нужен ID магазина. Запустите выгрузку и откройте её результат через историю запусков.

Расписание использует время компьютера. Закрытие окна оставляет приложение в системном трее. Команда **Выйти после выполнения задач** останавливает планировщик и дожидается активных задач.

В **Выгрузках** и **Журнале** отображается прогресс запросов. Повтор при временной ошибке входит в тот же запрос. При пагинации или ожидании зависимых данных остаток уточняется во время запуска. В колонке **Завершение** видны время и полная длительность, включая очередь, ожидание лимита, обработку и запись файлов. Для старых запусков время восстанавливается по сохранившимся журналам.

У параметров типа `date` и `datetime` можно выбрать фиксированное значение или смещение в календарных днях от даты запуска по часам компьютера. Например, для периода «вчера — сегодня» задайте смещения `-1` и `0`. Ручной запуск использует то же правило. Даты фиксируются при постановке запуска в очередь и сохраняются для всех страниц, повторов и возобновления.

Для ввода в JSON относительная дата задаётся как `{"daysFromRun":-1}`, а дата со временем — как `{"daysFromRun":-1,"time":"09:30"}`. В массиве или объекте правило применяется к элементам и полям, которым в шаблоне задан тип `date` или `datetime`.

Сборка папки для Windows x64:

```powershell
npm run package:windows
```

Результат находится в `dist/MP API-win32-x64`. Переносите всю папку и запускайте `MP API.exe` из каталога с правом записи. Рядом с программой создаются `data`, `exports` и `logs`. Для разработки можно задать другой каталог в `MP_API_HOME`. Локальные ключи хранятся в зашифрованном виде через Electron safeStorage и вводятся отдельно на каждом компьютере.

## Настройка шаблонов

Подключение хранит именованные адреса, профили заголовков и общие лимиты. Черновик можно проверить до публикации. Выгрузки используют опубликованные версии, а каждый запуск фиксирует версию шаблона, параметры, адрес и версии справочников. Пакеты настроек переносят подключения и шаблоны. Они открываются как черновики и не содержат сохранённых ключей.

Во вкладке **Шаблоны запросов** выберите подключение и папку. **Где используется** показывает выгрузки, обработки и зависимые запросы. Архивные шаблоны доступны действующим выгрузкам и цепочкам, их можно восстановить из **Архива**. Полное удаление доступно после снятия ссылок и завершения текущих запусков.

В редакторе есть поля метода, пути, параметров и колонок. Дополнительные правила задаются в JSON. Пример параметров с вложенным полем тела и разбиением списка:

```json
[
  {"name":"active","where":"body","key":"filter.active","type":"boolean","default":false},
  {"name":"ids","where":"body","type":"array","items":{"type":"integer"},"batchSize":200}
]
```

- `where` принимает `path`, `query`, `body`, `header` и `input`. Для массива в корне тела укажите `where: "body"` и `key: "$"`. Параметры `input` заполняются в форме запуска и могут подставляться в `reference.fields` через `$input.имя`. Типы включают строки, числа, целые, даты, логические значения, объекты и массивы. Можно указать `required`, `nullable`, `min`, `max`, `minItems`, `maxItems`, `enum` и `unique`. `maxItems` ограничивает весь запуск, `batchSize` задаёт размер части, `splitForBody` разрешает делить список для соблюдения лимита байт.
- Для диапазона дат укажите `{"from":"dateFrom","to":"dateTo","daysPerRequest":30}`. Даты в UI вводятся в формате `YYYY-MM-DD`. Форматы `unix-start` и `unix-end` переводят границы дня в секунды UTC.
- Настройте режим пагинации и пути к курсору. Для страниц и смещения доступны условия `empty`, `short`, `flag` и `total`. Аномалия курсора оставляет сохранённые строки и помечает источник неполным.
- Путь к строкам ответа, например `result.shipments`, отделён от колонок. Путь `$` выбирает корень ответа. Для ответа из одного объекта включите `singleObject` в дополнительных правилах ответа. Вложенные массивы попадают в ячейку JSON-текстом. Параметр ответа `expand` разворачивает один указанный массив в основном листе, `tables` добавляет отдельные таблицы. В колонках можно сослаться на `$item` или `$parent`. Для явного удаления дублей укажите `deduplicateBy`.
- В параметрах можно задать `reference: {"templateId":"…","path":"warehouse_id","mode":"many"}`. Режимы `one` и `many` позволяют выбрать значения, `all` передаёт список. Обновление справочника выполняется вручную из опубликованного шаблона того же подключения.

Полученные страницы хранятся на диске, метаданные и контрольные точки — в SQLite. Безопасные шаблоны с разрешённым возобновлением продолжаются после прерывания. Для остальных доступно повторное выполнение и экспорт сохранённой части. XLSX содержит листы источников и делится на файлы при достижении предела строк. CSV создаётся отдельно для каждой таблицы. При неполной выгрузке в папке есть файл `результат.json` со статусами источников.

## Редактор обработок

В редакторе **Обработок** можно добавлять, переставлять и изменять шаги. Нажмите название шага, чтобы раскрыть его настройки. Доступны фильтр, проверка полей, разворот массива или нескольких объектов и перенос полей. После них задаются колонки результата. В режиме **JSON** можно редактировать те же массивы `steps` и `columns`.

Для проверки правил выберите сохранённый запуск и нажмите **Предпросмотр**. В таблице видны количество строк и ошибки на каждом шаге. Под таблицей можно открыть образцы результата каждого шага.

### Воронка Wildberries по периодам

1. Опубликуйте шаблон `POST /api/analytics/v3/sales-funnel/products` с путём к строкам `data.products`.
2. В разделе **Обработки** нажмите **Новая обработка**, выберите этот шаблон и сохраните **Воронку WB по периодам**. Названия и состав колонок можно отредактировать там же.
3. Для новых запусков выберите сохранённую обработку в поле **Обработка** у источника в редакторе выгрузки. Это работает и для выгрузок по расписанию.
4. Для полученного ранее ответа откройте **Журнал → Подробнее → Применить обработку** у нужного источника. Выберите формат и нажмите **Создать файл**. Обработка читает сохранённые страницы запуска. Новый файл доступен по кнопке **Открыть обработанные файлы**.

В результате повторяются артикул WB, название, артикул продавца, бренд и суммарный остаток. Строки текущего и предыдущего периодов получают свои даты и показатели. При отсутствии предыдущего периода остаётся одна строка. Блок `comparison` не содержит границ периода и в таблицу не попадает. Вложенные показатели `timeToReady`, `wbClub` и `conversions` выводятся отдельными колонками. Количество строк каждой таблицы записывается в `результат.json`.

## Запросы с зависимостями

Режим `reference.refresh: "run"` запускает опубликованный шаблон в том же подключении перед основным запросом. Для списка можно выбрать вложенный массив через `expand` и взять одно поле через `path` или собрать объект через `fields`. Прежний режим справочника обновляется вручную.

Чтобы отобрать записи зависимого ответа до разворота `expand`, укажите `reference.filter` с путём `path` и списком допустимых `values`.

Для статистики поисковых кластеров Wildberries доступен [пакет из трёх шаблонов](examples/wb-search-clusters.json) и [пошаговая настройка](docs/wb-search-clusters.md).

Для загрузки медиакампаний по ID из списка доступна [пошаговая настройка](docs/wb-media-campaigns.md).

Для статистики WB Медиа с выбранными датами и зависимым списком кампаний используйте [инструкцию по `POST /adv/v1/stats`](docs/wb-media-statistics.md).

Для статистики рекламы с отбором статусов, пакетами по 50 кампаний и разбивкой по дням используйте [инструкцию по `GET /adv/v3/fullstats`](docs/wb-fullstats.md).

Чтобы объединить `fullstats`, состав кампаний и воронку в одной книге, настройте [«Свод РК» по брендам и периодам](docs/wb-campaign-summary.md).

Соединения источников, итоговые показатели и листы можно настроить во вкладке **Обработки**. [Обработка всей выгрузки](docs/workbook-processing.md)

## Проверка

```sh
npm test
```

Тесты поднимают локальные HTTP-заглушки для трёх методов. Они проверяют сериализацию, разбиение, пагинацию, хранение больших целых, контрольные точки, неполные ответы, выгрузку файлов, лимиты, расписание и перенос шаблонов. Для проверки живых API нужны ключи и доступ к адресам поставщиков. Отдельный лимит Ozon v2, границы периодов Wildberries и окончание пагинации проверяются при первых живых запросах.

### Диагностика подключения

В подробном журнале запуска событие `request` показывает метод, адрес и имена полей. Значения параметров и ключей скрыты. Событие `http` содержит статус ответа, а `network_error` — код сетевой ошибки и длительность попытки. Например, `ERR_NAME_NOT_RESOLVED` указывает на DNS, `ERR_TUNNEL_CONNECTION_FAILED` — на соединение через прокси, `ERR_CERT_AUTHORITY_INVALID` — на проверку сертификата. Приложение использует сетевой стек Electron с системными настройками прокси.

Из PowerShell можно проверить, отвечают ли серверы по HTTPS, без передачи ключей:

```powershell
curl.exe -I --connect-timeout 10 --max-time 20 https://api-seller.ozon.ru/
curl.exe -I --connect-timeout 10 --max-time 20 https://api.partner.market.yandex.ru/
```

Ответ от самого API, даже `401`, `403` или `404`, показывает, что HTTPS-соединение установлено. Проверка авторизации выполняется из приложения на конкретном методе API.
